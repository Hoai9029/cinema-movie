Project Summary - CineStream

Overview:
- CineStream is a Flutter movie streaming/demo application.
- It uses Firebase Authentication for email/password login and Provider for state management.
- The app supports dark/light theme switching and a multi-tab navigation layout.

Core Architecture:
- Entry point: lib/main.dart
  - Initializes Firebase using firebase_options.dart.
  - Sets up MultiProvider with WatchlistState and ThemeModeState.
  - Launches the app with MaterialApp and dynamic theme selection.

Screens and Navigation:
- SplashPage (lib/pages/splash_page.dart)
  - Displays app logo and loading indicator for 2 seconds.
  - Navigates automatically to LoginPage.
- LoginPage (lib/pages/login_page.dart)
  - Allows users to sign in or register with email and password.
  - Uses FirebaseAuthRepository for authentication.
- HomePage (lib/pages/home_page.dart)
  - Main app shell with BottomNavigationBar and four tabs:
    - Home
    - Categories
    - Favorites
    - Profile
- CategoriesPage (lib/pages/categories_page.dart)
  - Displays a grid of movies grouped by genre, fetched live from TMDB
    (TmdbMovieRepository.fetchMoviesByGenre / searchMovies).
- FavoritesPage (lib/pages/favorites_page.dart)
  - Shows movies marked as favorites via WatchlistState.favoriteMovies (the full
    Movie objects are stored in WatchlistState itself, not looked up elsewhere).
- ProfilePage (lib/pages/profile_page.dart)
  - Displays static profile info, watch history, and a theme toggle.

Movie Details and Playback:
- MovieDetailPage (lib/pages/movie_detail_page.dart)
  - Backed by MovieDetailCubit (lib/cubit/movie_detail_cubit.dart), which fires 4 TMDB
    requests in parallel (detail, credits, videos, similar movies) via a Dart records
    `.wait`, and exposes Initial/Loading/Loaded/Error states (lib/cubit/movie_detail_state.dart).
  - Shows backdrop/poster, title, rating, runtime, genre chips, overview, a horizontally
    scrolling cast list (photo + name), and a horizontally scrolling "similar movies" list.
  - Tapping a similar movie pushes a new MovieDetailPage for it (recursive navigation).
  - Allows toggling favorite status and navigating to WatchPage.
  - Dedicated loading spinner and error view with a retry button.
  - Trailer preview: the circular play button on the backdrop header only renders when
    MovieDetailBundle.trailerVideo (first video with type == "Trailer" and
    site == "YouTube") is non-null; tapping it pushes TrailerPlayerPage. No trailer
    means the button is simply hidden (no crash, no dead control).
  - Hero animation: accepts an optional `heroTag` constructor param (defaults to
    'poster-${movie.id}') and wraps the header poster/backdrop in a matching Hero.
    Because the header shows movie.poster as a fallback until the TMDB detail call
    resolves, and the destination route builds synchronously on push (before that
    async fetch completes), the Hero flight always animates poster -> poster; the
    later swap to the real backdrop is a plain post-flight content update, not part
    of the animation.
- TrailerPlayerPage (lib/pages/trailer_player_page.dart)
  - Plays the YouTube trailer in-app via youtube_player_flutter's YoutubePlayer widget.
- WatchPage (lib/pages/watch_page.dart)
  - Simulates a movie playback experience with a timer and seek slider.

Data and Services:
- Movie model: lib/models/movie.dart
  - Defines movie properties such as id, title, poster, duration, rating, overview, and genre.
- TMDB repository: lib/data/repositories/tmdb_movie_repository.dart
  - Fetches trending/genre/search movies from TMDB using the `http` package.
- TMDB Retrofit API: lib/data/api/tmdb_api.dart (+ generated tmdb_api.g.dart)
  - Dio/Retrofit client used only by MovieDetailCubit for movie detail, credits,
    videos, and similar-movies endpoints.
- TMDB Dio client: lib/data/api/tmdb_dio_client.dart
  - Builds the Dio instance and injects the TMDB API key/bearer token via an interceptor.
- TMDB detail models: lib/data/models/tmdb_movie_detail_response.dart
  - json_serializable models for movie detail, genres, cast, and videos.
- TMDB config: lib/config/tmdb_secrets.dart
  - Stores TMDB API key and access token.
- Firebase Auth repository: lib/data/auth/firebase_auth_repository.dart
  - Handles sign in, registration, sign out, and auth state changes.
- App state:
  - WatchlistState (lib/data/watchlist_state.dart): manages favorite movies, keyed
    by id but storing the full Movie object (poster/title/etc. come from TMDB, so
    the favorites screen needs more than just an id to render).
  - ThemeModeState (lib/data/theme_mode_state.dart): manages light/dark theme state.

Theme and UI:
- App theming: lib/core/theme/app_theme.dart
  - Defines dark and light ThemeData.
- Colors and shared styling are centralized in lib/core/theme/app_colors.dart.
- Reusable widgets:
  - MovieCard (lib/widgets/movie_card.dart): takes an optional `heroTag`; when set,
    wraps the poster image in a Hero so it can fly into MovieDetailPage's header.
  - ResponsiveContainer (lib/widgets/responsive_container.dart)
  - SectionTitle (lib/widgets/section_title.dart)

Notes:
- The app is primarily a movie browsing/demo app rather than a full streaming service.
- All movie data now comes live from TMDB — the old local dummy dataset
  (lib/data/fake_movies.dart, ids '1'-'6') has been removed. Every screen (Home,
  Categories, Favorites, Movie Detail) works off real TMDB ids and Movie objects
  passed via navigation arguments; app_router.dart's dynamic /movie/:id and
  /watch/:id routes no longer have a fake-data fallback for that reason.
- User authentication requires Firebase configuration to work properly.
- Two TMDB integration styles coexist: most screens use the plain `http`-based
  TmdbMovieRepository + FutureBuilder, while MovieDetailPage uses Dio/Retrofit +
  flutter_bloc (MovieDetailCubit), per that ticket's technical requirements.
- No `language` query parameter is sent to TMDB anywhere in the app (removed from
  TmdbApi and TmdbMovieRepository). It previously hardcoded 'vi-VN', but TMDB's
  /movie/{id}/videos endpoint filters strictly to that exact language tag with no
  fallback — most movies have no Vietnamese-tagged trailer, so the trailer button
  was empty for nearly everything except titles with official VN marketing (e.g.
  "The Odyssey"). Removed everywhere, not just videos, to keep API behavior
  consistent across detail/credits/videos/similar/discover/search.
- Hero poster tags on the Home tab are namespaced per row, not just per movie id
  (see HomePage._buildMovieRow's `sectionKey` param, e.g.
  'poster-trending-${movie.id}' vs 'poster-genre-Action-${movie.id}'). TMDB's
  "popular" and per-genre discover results frequently overlap (the same blockbuster
  shows up in Trending AND a genre row), and Flutter hard-crashes if two Hero
  widgets share a tag while mounted on the same route simultaneously. The tag is
  generated at the tap site and passed straight through to the pushed
  MovieDetailPage's `heroTag`, so source/destination always match per-tap while
  staying unique across rows. FavoritesPage/CategoriesPage don't use MovieCard, so
  they get MovieDetailPage's default 'poster-${movie.id}' tag with no Hero
  animation (harmless, just no flight).
